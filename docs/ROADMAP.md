# x-media-archiver Roadmap

> 状态：活跃路线图
>
> 最后更新：2026-08-14
>
> 产品方向：在可信归档底座之上，把项目升级为可检索、可整理的个人媒体库。

## 当前事实基线

项目已经具备：

1. CLI、API 与 WebUI 共享的数据库归档队列，以及逐 Tweet 下载、回填、校验和重试审计。
2. 来源发现、原生 cursor 历史扫描、可恢复扫描会话、批量任务和命名定时策略。
3. Archive Queue、Sources、Feed、Search、Insights、Library、Collections、Tweet Detail、Failures、Duplicates 与 Operations 页面。
4. 单管理员认证、Cookies 检测、结构化日志、SSE 与只读 WebSocket 运行态投影。
5. 按 `media_assets.id` 精确执行的媒体物理删除、SHA-256 重复项治理和删除审计。
6. Ruff、后端单元/集成测试、WebUI build、扩展 build 与 Playwright E2E 工作流。

当前架构继续保持单管理员、单实例和本地优先。除非部署目标发生变化，不引入多租户、分布式 worker 或跨进程 runtime bus。

## M0：可信底座与事实收敛

目标：在新增媒体库能力前，先证明来源发现到本地文件的核心链路不会漏归档、重复下载或无期限卡住。

### 自动化与受控真实验收

- [x] 用测试数据库覆盖 native cursor 的结束、不足一批、空批和 checkpoint 推进条件。
- [x] 验证暂停、恢复、停止及 API 重启后的 checkpoint 延续。
- [x] 验证扫描与下载共享单网络 worker 时不会并发启动外部下载器，且两类任务不会饥饿。
- [x] 用可控模拟覆盖 `rate_limited` / `auth_required` 暂停自动扫描，以及 `network_error` 不推进 cursor 的语义。
- [x] 经用户明确授权后，使用指定来源和本地 Cookies 完成 5 条发现、提交、下载、回填与校验闭环。
- [x] 在 `docs/testing/source-scanning-acceptance.md` 记录环境、输入范围、结果和遗留问题。

真实手机锁屏恢复、飞牛 NAS、Traefik/应用重启及完整备份恢复演练并行记录，但不阻塞 M1。

### 事实修正

- [x] 移除 Dashboard 根据当前总数生成的模拟趋势与“24h 活动”。
- [x] 移除没有对应路由的 `/demo` 导航。
- [x] 修正 README、部署指南、WebUI 说明和手工验收中的删除能力与文档断链。
- [x] 完成受控验收后，把结论同步到下载器契约和手工验收清单。

## M1：Tweet 级全局搜索

目标：让历史归档内容可以快速找回，而不是继续依赖页面内 `%ILIKE%` 基础筛选。

### 数据与 API

- [x] 新增搜索所需的 Alembic revision；迁移必须可升级、可降级。
- [x] 使用 PostgreSQL 全文检索与 trigram 支持中英文混合查询，不引入外部搜索服务。
- [x] 以 Tweet 为结果单位，覆盖 Tweet 文本、作者、标签、合集和私人备注。
- [x] 支持来源、日期、媒体类型、归档状态、标签和合集筛选。
- [x] 有关键词时按相关度排序；无关键词时按发布时间倒序；支持相关度、最新和最早切换。
- [x] 对合成的 10 万至 100 万级 Tweet 数据执行搜索基准，不读取真实归档内容。

### WebUI

- [x] 新增独立搜索页面，查询、筛选和排序全部同步到 URL。
- [x] 默认展示已归档内容，可显式筛选失败、缺失和处理中记录。
- [x] 提供模糊匹配、结果高亮、加载态、空态和错误态。
- [x] 桌面与窄屏布局均可用，并复用现有帖子卡片和预览体验。

## M2：标签、合集与私人备注

目标：为归档后的主题整理和个人上下文提供轻量、可持续的工作流。

### 数据语义

- [x] 平面标签库支持名称、规范化名称、颜色和描述；标签大小写不敏感唯一。
- [x] Tweet 可属于多个手工合集；合集支持名称、描述和从已有媒体中选择封面。
- [x] Tweet 支持单条纯文本私人备注和更新时间；标签、合集与备注通过统一事务显式保存。
- [x] 媒体物理删除或来源软删除后，Tweet 的标签、合集和备注继续保留。
- [x] 删除标签或合集时展示影响数量并二次确认，只解除整理关联，不删除 Tweet 或媒体。

### WebUI

- [x] 新增独立的“合集”与“自定义标签”页面，支持合集帖子流详情以及标签搜索、排序和维护。
- [x] Feed 提供快捷整理，Tweet Detail 提供完整编辑。
- [x] 关闭存在未保存整理更改的弹窗时要求确认放弃；保存失败时保留当前输入。
- [x] Library 明确区分 Tweet 级“整理模式”和媒体 ID 级“删除模式”。
- [x] 整理模式支持最多 200 条 Tweet 的批量加减标签与加入/移出合集。
- [x] 帖子卡片默认最多展示三个标签、合集数量和备注标记。

## M3：工程设计文档

目标：为当前系统补齐可审查、可版本化且与代码事实一致的工程设计入口，降低后续维护与架构演进成本。

- [x] 新增系统上下文、部署拓扑、应用分层和三条核心数据流图。
- [x] 按归档队列、来源扫描、检索整理和认证审计拆分核心 ER 图。
- [x] 记录队列租约、写锁、外部子进程、媒体删除、启动恢复和实时收敛策略。
- [x] 建立架构文档与 ADR 索引，补录单网络 worker、双持久化边界和只读运行态投影决策。
- [x] 使用 Mermaid CLI 验证新增图表可渲染，并执行内部链接与敏感信息检查。

## M4.1：只读归档洞察

目标：先用现有数据库事实回答“归档里有什么、何时产生、整理得怎样”，不引入新的写路径或外部依赖。

- [x] 新增只执行数据库查询的 `GET /api/v1/library/insights`；不扫描文件、不访问 X、不改变归档状态。
- [x] 分开展示 Tweet 真实发布时间与归档入库时间，避免用当前总数伪造历史趋势。
- [x] 展示媒体类型/状态、已知体积与视频时长、作者空间占用、整理覆盖率和元数据完整率。
- [x] 来源发现、来源下载提交和当前校验状态按 Tweet 去重展示，并明确它们不是严格线性漏斗。
- [x] WebUI 覆盖加载、空、错误、窄屏与调试脱敏状态；后端集成测试证明读取前后事实行不变。

## M5：平台 Hashtag

目标：把 gallery-dl 已经写入媒体元数据文件的平台 Hashtag 作为只读 Tweet 事实保留下来，并与人工“自定义标签”明确分离。

### M5.1：后端事实与检索契约

- [x] 新增独立 `hashtags` / `tweet_hashtags` 数据模型；使用 Unicode NFKC + casefold 判重，并按 Tweet 保留首次显示写法与位置。
- [x] 仅在 gallery-dl 下载成功并完成媒体回填后读取数据库已登记的元数据文件；不读取扫描缓存、正文、浏览器扩展输入或 yt-dlp 元数据。
- [x] 采用只增不减语义：新的观察可补充关系，缺失、空数组或后续变化都不会删除既有平台 Hashtag。
- [x] 提供默认 dry-run、需 `--apply --confirm` 才写入的历史维护命令；只扫描 `media_assets.metadata_path`，不递归扫描磁盘、不访问 X。
- [x] 平台 Hashtag 进入 Feed、Search 与 Tweet Detail API，支持精确单值筛选、有界联想和全文搜索；不与自定义 `tags` 混用。
- [x] 记录当前 gallery-dl 版本和已验证版本；未知版本只告警、不阻断下载或应用启动。

### M5.2：WebUI 展示与筛选

- [x] Feed、Search、媒体预览和 Tweet Detail 以文字与结构区分平台 Hashtag 和自定义标签。
- [x] 点击平台 Hashtag 后进入可复制、刷新后保持的精确搜索 URL；筛选联想按需加载且每次最多 20 条。
- [x] 覆盖桌面、窄屏、加载、空、错误和调试脱敏状态。

### 后续数据完整性事项

- [ ] 单独修复来源提交下载时瘦记录覆盖 `tweets.raw_import` 的问题；该缓存问题不作为平台 Hashtag 的事实来源，也不阻塞 M5。

## 每个里程碑的完成标准

- 数据库 revision 的 upgrade/downgrade 均有验证。
- API response/request schema 与 WebUI generated types 同步。
- 页面覆盖桌面、窄屏、加载态、空态和错误态。
- 后端改动通过 Ruff 和相关定向测试；WebUI 改动通过 build。
- `git diff --check` 通过，README、Roadmap 与手工验收文档同步。

## 本轮明确不做

- 浏览器扩展直投本地 API。
- OCR、字幕转写、语义搜索、相似媒体或其他模型依赖。
- 层级标签、标签同义词、智能合集、保存筛选。
- 合集嵌套、自定义封面上传、逐条拖拽排序。
- Markdown 备注、备注版本历史或附件。
- 强制“待整理”流程、独立收藏/星标模型。
- 标签、合集和备注的导出与恢复。
- 从 Tweet 正文、X Article、引用/转推嵌套内容推断 Hashtag，或由浏览器扩展、API、JSONL、yt-dlp 提供平台 Hashtag。
- 基于平台 Hashtag 自动创建自定义标签、加入合集或触发下载。
- 多用户权限、WS 写命令、分布式 worker 与公网 SaaS 化。

## 安全边界

1. 不默认对真实 X 账号执行批量扫描或下载；真实验收必须由用户指定来源与数量。
2. 普通来源扫描不隐式提交下载；下载必须由人工动作或已启用的明确策略触发。
3. 媒体删除继续按 `media_assets.id` 精确执行，限制在 `archive/media`，保留 Tweet、任务历史和删除审计。
4. 不提交 Cookies、生产连接串、真实媒体或用户导出数据。
